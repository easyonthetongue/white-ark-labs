# White Ark Labs website

A fast, zero-dependency static website for a Pakistan-based leather goods product-development and managed-manufacturing partner. The supplied White Ark visual language remains the design foundation.

## Local preview

Requires Node.js 20 or newer.

```sh
npm run dev
```

Open `http://localhost:4173`. Saved changes rebuild the site and refresh the preview automatically.

```sh
npm test
npm run build
```

The production site is generated in `dist/`.

## Source of truth

All published catalogue data lives in `src/data/catalogue.mjs`:

- `categories` — five product families
- `products` — 46 normalized product references
- `materials` — six material families
- `techniques` — 12 craftsmanship techniques
- `constructionCapabilities` — 12 construction and finishing capabilities

The build validates IDs, slugs, required fields and every relationship before generating pages. Do not copy product records into page templates.

To add a product:

1. Add one seed entry to `productSeeds` in `src/data/catalogue.mjs` with a unique `WAL-###` ID and slug.
2. Reference an existing category, material and technique ID.
3. Adjust the expected category count in `scripts/validate-data.mjs` only if the approved catalogue target changes.
4. Run `npm test` and resolve every validation or link failure.

Material and technique records automatically derive their related-product lists from product relationships.

The complete disposition of the former 89-item prototype is recorded in `src/data/catalogue-audit.json` and regenerated by `scripts/audit-legacy.mjs`.

## Quote delivery configuration

The form never displays success unless a server accepts the request. Configure either of these values in `src/data/site.json` before publishing:

- `quoteEndpoint` — an HTTPS server-side endpoint that accepts `multipart/form-data` and returns a 2xx response only after securely accepting the lead.
- `quoteRecipient` — reserved for direct-contact presentation if required; it is not used as a fake form delivery mechanism.

The endpoint must handle file uploads, server-side validation, spam controls, secure storage or email delivery, and appropriate privacy retention. Never add provider secrets to browser code.

Set the canonical production origin at build time:

```sh
SITE_URL=https://your-domain.example npm run build
```

Local builds use `http://localhost:4173`. The included GitHub Pages workflow takes its canonical origin from the Pages configuration automatically.

## Deployment

1. Create or choose a GitHub repository.
2. Push this project to the `main` branch.
3. In **Settings → Pages**, select **GitHub Actions** as the source.
4. Confirm the `Deploy static site to GitHub Pages` workflow succeeds and open the resulting Pages URL.

No deployment should be considered live until that final URL is verified.
# Repository product catalogue sync

The source of truth is `catalog/products/` in this repository. Each SKU folder must contain `01-front.jpg`, `02-three-quarter.jpg`, `03-side.jpg`, `04-detail.jpg` and `product-description.txt`. The sync writes local product data to `src/data/imported-products.mjs` and copies images into `src/assets/catalogue/`; public pages never call an external service.

## Run a sync

```sh
npm run products:sync -- --dry-run
npm run products:sync -- --sku=WAL-041
npm run products:sync -- --force
npm run build
```

The sync is idempotent using SKU and content fingerprints. It prevents concurrent runs with a lock, preserves previously imported products when a source folder is removed, and reports product-level failures. `--dry-run` validates and reports changes without writing records or images.

## Admin dashboard

Run the local Node server with `ADMIN_SYNC_TOKEN` configured, then open `/admin/products/`. GitHub Actions runs the same CLI sync automatically before building and deploying Pages. No Google credentials are required.

## Troubleshooting

Validation errors identify the product folder and field. Corrupt or missing images are reported per product and prevent deployment when synchronization has critical failures.

## Adding products later

Create `catalog/products/WAL-041/`, add the four exact JPG filenames and a description file, then commit and push to `main`. The GitHub Actions workflow runs `npm run products:sync`, builds the catalogue and deploys only if sync, build and tests pass. The product then appears in listings, search, its generated page and the sitemap. Existing manually authored products remain untouched.
